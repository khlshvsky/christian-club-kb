# База знаний Христианского клуба

Веб-сервис — база знаний по разделам богословия: вопросы и ответы с опорой на
Священное Писание, догматическое богословие, апологетику и историю Церкви.
Библейские цитаты оформлены как ссылки на синодальный перевод в «Викитеке».

**Содержание:** четыре вкладки и единый поиск по всему сайту (клавиша «/»).

- **Вопросы и ответы** — 263 вопроса в 17 разделах богословия — апологетика, учение о
Священном Писании, учение о Боге, триадология, космология и ангелология,
антропология, амартология, христология, сотериология, пневматология,
экклезиология, сакраментология, литургика, почитание святыни, эсхатология,
патрология и история Церкви, христианская этика.
- **Дерево терминов** — 697 богословских терминов в 7 частях, 23 ветвях и 74
  подгруппах, с определениями, ссылками на Писание и 1080 перекрёстными связями.
  Шесть видов: раскрывающееся дерево, схема (раскрываемое дерево по щелчку),
  круг (кольцевая диаграмма), граф связей, карта (площадь — число терминов) и
  алфавитный указатель. Ереси и учения, отвергнутые Церковью (42), отмечены
  знаком ⊘; у каждого — подробное опровержение: что утверждало заблуждение,
  что отвечает Писание, что говорили святые отцы и как решила Церковь.
- **Символ веры** — 12 членов Никео-Цареградского Символа на церковнославянском
  и русском, с толкованием по Катихизису свт. Филарета, разбором слов, ссылками
  на Писание, связанными терминами и вопросами.
- **Библия** — путеводитель по 77 книгам: разряд, число глав, автор и время по
  преданию, содержание, ключевые места и ссылка на книгу в «Викитеке».

Термины из словаря подсвечиваются прямо в тексте ответов: при наведении или
нажатии всплывает краткое определение. У каждого вопроса и каждой книги есть
кнопка «Ссылка» — она копирует постоянный адрес.

Это статический сайт (HTML + CSS + JS), без сборки и без сервера. Разворачивается
на Vercel «как есть».

## Локальный просмотр

Откройте `index.html` в браузере, либо запустите простой сервер:

```bash
python3 -m http.server 8000
# затем откройте http://localhost:8000
```

## Публикация: GitHub + Vercel

### Шаг 1. Создать репозиторий на GitHub

1. На GitHub нажмите **New repository**, назовите его, например, `christian-club-kb`,
   и создайте (можно приватный).
2. В папке проекта выполните:

```bash
git init
git add .
git commit -m "Первая версия базы знаний"
git branch -M main
git remote add origin https://github.com/<ВАШ_ЛОГИН>/christian-club-kb.git
git push -u origin main
```

> Локальный git-репозиторий уже инициализирован в этой папке и содержит первый
> коммит — достаточно добавить `remote` и выполнить `push`.

### Шаг 2. Развернуть на Vercel (проще всего — без командной строки)

1. Зайдите на **vercel.com** и войдите через свой аккаунт GitHub.
2. Нажмите **Add New → Project** и выберите репозиторий `christian-club-kb`.
3. Framework Preset — **Other** (Vercel сам определит статический сайт).
   Build Command и Output Directory оставьте пустыми.
4. Нажмите **Deploy**. Через несколько секунд сайт будет доступен по адресу
   вида `https://christian-club-kb.vercel.app`.

Каждый последующий `git push` в ветку `main` будет автоматически обновлять сайт.

### Альтернатива: развернуть через Vercel CLI

```bash
npm i -g vercel
vercel        # предпросмотр
vercel --prod # публикация
```

## Кэш браузера

В `index.html` у стилей и скриптов стоит метка версии, например
`assets/app.js?v=20261102e`. Меняя `styles.css`, `app.js`, `terms.js` или данные,
поменяйте метку (во всех ссылках сразу) — тогда у посетителей гарантированно
загрузятся новые файлы, а не старые из кэша браузера.

## Как добавлять и править вопросы

Всё содержимое — в файле `data/knowledge.js`.

- Каждый **раздел** — объект с полями `id`, `title`, `sub` и массивом `qa`.
- Каждый **вопрос** — объект `{ q, a, s }`: вопрос, ответ (HTML) и источник.
- **Ссылки на Писание** пишутся в двойных скобках: `[[Ин 3:5]]` или
  `[[Ин 3:5|текст ссылки]]`. Сокращения книг задаются в объекте `BOOKS`
  (сокращение → название страницы в «Викитеке»). Если книги нет в `BOOKS`,
  напишите ссылку обычным текстом.

## Как добавлять и править термины

Термины лежат в простых текстовых файлах `terms-src/*.txt` (по файлу на ветвь).
Формат описан в начале `terms-src/01-osnovy.txt`:

```
@ id | Название ветви | подзаголовок | id раздела вопросов | источники
## Подгруппа
- Термин {греч.} :: Определение со ссылкой [[Ин 1:1]] => Связанный термин; Другой
! Ересь :: Определение                 (знак «!» — учение, отвергнутое Церковью)
= Термин                               (ссылка на термин из другой ветви)
```

Части верхнего уровня и их цвета — в `terms-src/00-chasti.txt`.

Опровержения ересей лежат в `terms-src/oproverzheniya/*.txt`: блок начинается
строкой `### Название термина`, далее строки `Учение ::`, `Писание ::`,
`Отцы ::`, `Церковь ::`, `Важно ::`. Скрипт сборки предупредит, если у термина
со знаком «!» нет опровержения.
После правки выполните:

```bash
python3 tools/build_terms.py
```

Скрипт проверит, что все связи указывают на существующие термины и нет
повторов, и пересоберёт `data/terms.js`.

Ссылки на термин: `/#terms/graph/t:Ипостась` (вид — `tree`, `scheme`, `sun`,
`graph`, `map`, `abc`); на ветвь в дереве: `/#terms/tree/troica`.

## Адреса страниц

- вопрос: `/#q/chto-znachit-chto-bog-troica` (слаг из текста вопроса);
- термин: `/#terms/graph/t:Ипостась`, ветвь: `/#terms/tree/troica`;
- член Символа веры: `/#creed/8`, весь Символ: `/#creed`;
- книга Библии: `/#bible/Ис` (сокращение из словаря `BOOKS`).

Если переформулировать вопрос, его адрес изменится — старые ссылки на него
перестанут открывать вопрос.

## Символ веры и книги Библии

`data/creed.js` и `data/bible.js` — обычные JavaScript-файлы с пояснениями в
начале. Названия терминов в `terms`/`against` должны совпадать с деревом, а
тексты вопросов в `qa` — с вопросами в `knowledge.js` дословно.
